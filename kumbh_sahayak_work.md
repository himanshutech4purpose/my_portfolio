## 1. Natural language processing

### 1.1 BGE embedding finetuning

**Overview:**
**BGE (Base Global Encoder) embeddings** are dense vector representations generated by a pre-trained model designed for tasks like semantic search, clustering, and recommendation. They capture **semantic similarity** by encoding text or data points into a common vector space where similar items have closer distances. These embeddings are often used for efficient similarity search in large-scale datasets.

**Task:**
You are given corpus of data and query. Bge embedding gives a vector representation of words and sentences. **Cosine distance**, **dot product** and **euclidean** can be used as a metric.

**BGE Embedding (e.g., Bidirectional Generative Embedding):**
* **Type:** Semantic-based, dense vector representation.
* **Core Idea:** Embeddings represent text in high-dimensional space based on meaning. Similarity is measured using vector distances (e.g., cosine similarity).
* **Usage:** Works well for semantic search, clustering, and personalization tasks.

**Strength**
* **Semantic Matching:**
    * Captures the contextual and semantic relationships between words.
    * Finds relevant documents even when they use synonyms or paraphrases of the query terms.
* **Zero-Shot Capabilities:**
    * Can generalize to unseen queries and domains with minimal or no retraining.
* **Multilingual Support:**
    * Often supports multiple languages, allowing cross-lingual search.
* **Rich Features:**
    * Embeddings can encode complex features such as tone, intent, and relationships.

**Reference:**
* [FlagOpen/FlagEmbedding GitHub](https://github.com/FlagOpen/FlagEmbedding).
* This sheet contains a tutorial notebook for fine tuning embedding on your dataset.
* Fine-tuning a BGE (e.g., BigGraph Embeddings or similar vector-based embedding models) for a retrieval task involves adapting the model to generate embeddings that align with the retrieval requirements.

### 1.2 BM25 (best match 25)

**Overview:**
**BM25 (Best Match 25)** is a ranking function widely used in information retrieval to evaluate the relevance of documents to a query. It is based on **term frequency (TF)** and **inverse document frequency (IDF)**, accounting for term saturation and document length normalization. BM25 assigns higher scores to documents with query terms appearing frequently while balancing overly long documents to avoid bias.

**Task:**
You are given corpus of data and query. Bge embedding gives a vector representation of words and sentences. Cosine distance, dot product and euclidean can be used as a metric.

* **Type:** Lexical-based, sparse vector representation.
* **Core Idea:** A traditional information retrieval model based on term frequency and inverse document frequency (TF-IDF). Scores documents by keyword matches and their relative importance in the corpus.
* **Usage:** Performs well for keyword-based search in structured or textual datasets.

**The following table:**

| Feature | BGE Embedding | BM25 |
| :--- | :--- | :--- |
| Type | Semantic (dense vector) | Lexical (sparse vector) |
| Context Understanding | Strong | Limited |
| Synonym Support | Yes | No |
| Scalability | Resource-intensive | Lightweight |
| Explainability | Low | High |
| Setup Complexity | High | Low |
| Use Case | Semantic search, clustering | Keyword search, filtering |

## 2. DeepFake

### Brief Overview
The objective is to create **personalized customer message (CM) audio integrated with video** using advanced AI techniques.

**Components**
* **Lip Sync Services:**
    * Synchronizes the audio and video to generate lip-synced output.
    * Uses the **Wav2Lip** model.
* **Voice-Cloning:**
    * Generates audio from text by cloning a given voice.
    * Employs models like **xTTS v2** and **VITS**.

**Drawio Link Description:**
The document includes a Drawio link for an architectural diagram. ** The diagram illustrates the system components, including the Voice-Cloning models (xTTS v2 and VITS) used to generate audio from text, and the Lip-Sync Service (Wav2Lip) used to synchronize the generated audio with a video.

### Training Script
**Voice Cloning Setup:**
* **Environment:** Docker-based setup on Ubuntu.
* **Models Used:** xTTS v2 and VITS.

**Training Process:**
* **xTTS v2:**
    * Trained on two datasets:
        * **Google Transcribed Audio:** Better or comparable to the Gautam fine-tuned model.
        * **Suyash Single Word:** Model handles shorter audio but struggles with pronunciation.
* **VITS:**
    * **Free from hallucinations** and performed better than xTTS v2.
    * However, the model did not fully converge due to limited training time (only **15 minutes of audio**).

**Dataset Details:**
* **Original Audio:** Noisy; cleaned using **Nemo Toolkit** to extract vocals.
* **Google Transcribed Audio:**
    * Labelled with Google Speech-to-Text.
    * Audio lengths range from 500ms to 8 seconds (median: ~1 second).
    * [Huggingface Dataset Link](https://huggingface.co/datasets/himanshu23099/youtube_data?row=0).
* **Suyash Single Word:**
    * Created by identifying word boundaries.
    * Each audio clip corresponds to a single word.

**Challenges:**
* **Word Error Rate (WER)** introduced by Google Speech API and Bhashini.
* Poor quality of the original audio.
* Background frequencies persist despite cleaning.

### Testing Script
* **Audio Generation:** Generated audio using voice cloning with a list of Hindi names (TTS).
* **Name Verification:** Used **Bhashini** for name recognition (STT).

### Key Insights
* **Training Time:** Both VITS and xTTS v2 require about a day or 2 to train effectively.
* **Model Comparison:**
    * **xTTS v2:**
        * **Strength:** Versatile with varied conditions.
        * **Weakness:** Prone to hallucinations.
    * **VITS:**
        * **Strength:** Stable and hallucination-free.
        * **Weakness:** Training requires more time and better datasets for full convergence.

## 4. DeepFake audio

### Technical Overview:
**Key Architectural Evolution**
* **2016:** WaveNet introduced autoregressive raw waveform synthesis.
* **2018:** Tacotron 2 pioneered attention-based mel-spectrogram synthesis.
* **2020:** Glow-TTS and FastSpeech reduced latency with non-autoregressive flows.
* **2021:** **VITS** unified TTS and vocoder in a single end-to-end model.
* **2023:** Diffusion models enabled real-time and multi-modal synthesis.

**Autoregressive model**
* **Error Propagation:** Autoregressive models rely on sequential dependencies, where early prediction errors compound, leading to artifacts or degraded audio quality over time.
* **Prosody Limitations:** They struggle to model natural rhythm and intonation effectively, often producing monotonous or unnatural-sounding speech without additional prosody control mechanisms.

**Diffusion Models**
